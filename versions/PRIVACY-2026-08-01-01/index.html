Политика обработки персональных данных

Версия PRIVACY-2026-08-01-01 · 1 августа 2026 года

Настоящая политика описывает обработку данных в Android-приложении FitTrack. Она применяется к обеим сборкам приложения: ik1ant.fittrack.android, распространяемой через RuStore, и ik1ant.fittrack.android.huawei, распространяемой через Huawei AppGallery. Сборки различаются только идентификатором рекламного места; состав обрабатываемых данных, цели обработки и получатели одинаковы. Оператор приложения — Зайнутдинов Ильяс Хасмагомедович. Контактный адрес электронной почты: ik1ant484@gmail.com.

Кратко: тренировки можно вести полностью локально без аккаунта. При создании нового аккаунта в этой версии Android-приложения пользователь предоставляет отдельное согласие на обработку персональных данных. Данные Health Connect читаются только с отдельного разрешения и не передаются третьим лицам. Неперсонализированная реклама Яндекса является частью интерфейса приложения.

1. Какие данные обрабатываются

  • email, имя или никнейм и технический UID учётной записи;
  • сведения о предоставлении согласия при регистрации: дата, версия согласия, версия настоящей политики и платформа Android;
  • программа тренировок: упражнения, описания техники, веса и повторения;
  • по отдельному разрешению — суммарно сожжённые за текущий день калории из Health Connect;
  • технические сведения, необходимые для сетевого соединения, защиты и диагностики сервисов, включая IP-адрес и служебные сведения запросов;
  • при показе рекламы — технические сведения устройства и рекламного запроса, необходимые Yandex Mobile Ads для загрузки, показа и диагностики баннера.

Пароль обрабатывается Firebase Authentication и не сохраняется в хранилище тренировок приложения.

2. Цели и основания обработки

Данные аккаунта и программы тренировок используются для регистрации, входа, восстановления доступа, синхронизации между устройствами, поддержки и обеспечения безопасности. При создании нового аккаунта в этой версии Android-приложения пользователь отдельно предоставляет согласие редакции ACCOUNT-SYNC-CONSENT-2026-08-01-01. Гостевой режим не отправляет тренировки в облако. Для ранее созданных аккаунтов применяются условия и подтверждения, действовавшие при их регистрации.

3. Health Connect

FitTrack читает только суммарно сожжённые калории за текущий день после явного разрешения пользователя. Эти сведения отображаются на устройстве, не сохраняются приложением, не включаются в облачную синхронизацию и не передаются Firebase, рекламным системам или иным третьим лицам. Разрешение необязательно и может быть отозвано в настройках Health Connect без ограничения остальных функций FitTrack.

На устройствах без сервисов Google, включая часть устройств Huawei, компонент Health Connect может отсутствовать. В этом случае приложение сообщает о недоступности, не запрашивает разрешение и работает в полном объёме без этих данных.

4. Firebase, территории обработки и хранение

Для аутентификации и синхронизации используются Firebase Authentication и Cloud Firestore (Google). По информации Firebase, Firebase Authentication обрабатывает данные аутентификации в США, а Cloud Firestore обрабатывает данные в выбранном для проекта регионе инфраструктуры Google. Использование облачного режима может включать трансграничную передачу данных. Локальный гостевой режим не использует Firebase.

Локальные данные находятся во внутреннем хранилище Android. Сетевой обмен выполняется по TLS, незашифрованный HTTP запрещён, системное резервное копирование данных приложения отключено.

5. Реклама Яндекса

В публичных Android-сборках подключён Yandex Mobile Ads SDK. Рекламное место зависит от сборки: R-M-19665468-1 в сборке ik1ant.fittrack.android для RuStore и R-M-19683621-1 в сборке ik1ant.fittrack.android.huawei для Huawei AppGallery. В отладочных сборках используется официальный тестовый идентификатор demo-banner-yandex. SDK инициализируется при запуске приложения, а рекламный баннер является частью интерфейса. Яндекс может получить IP-адрес и технические сведения устройства и рекламного запроса, необходимые для загрузки, показа и диагностики баннера.

FitTrack передаёт рекламному SDK значение setUserConsent(false), отключает передачу геолокации и удаляет разрешение на Advertising ID (AD_ID) из итоговой сборки Android. Персонализированная реклама не включена. Отдельное отключение рекламного баннера в приложении не предусмотрено.

6. Срок хранения и удаление

Локальные данные хранятся до удаления данных приложения или самого приложения. Облачные данные хранятся до удаления учётной записи, отзыва согласия либо достижения целей обработки, если более длительная обработка не требуется законом. Удалить учётную запись и облачные тренировки можно на экране «Аккаунт».

После отзыва согласия облачный аккаунт и синхронизация становятся недоступны. Локальный гостевой режим продолжает работать.

9. Изменения политики

При изменении состава данных, целей обработки, облачных сервисов или рекламной конфигурации оператор обновит эту политику и её версию. Необходимость получения нового согласия определяется с учётом характера изменений и требований применимого законодательства.
