Политика обработки персональных данных

Версия PRIVACY-2026-08-08-03 · 8 августа 2026 года

Настоящая политика описывает обработку данных в Android-приложении FitTrack ik1ant.fittrack.android, распространяемом через RuStore. Оператор приложения — Зайнутдинов Ильяс Хасмагомедович. Контактный адрес электронной почты: ik1ant484@gmail.com.

Кратко: тренировки можно вести локально без аккаунта. Аккаунт и синхронизация необязательны. Данные Health Connect читаются только с отдельного разрешения и не передаются третьим лицам. Примерное местоположение передаётся Open-Meteo только после отдельного разрешения для показа погоды и не сохраняется FitTrack. Неперсонализированная реклама Яндекса является частью интерфейса.

1. Какие данные обрабатываются

  • email, имя или никнейм и технический UID учётной записи;
  • сведения о предоставлении согласия при регистрации: дата, версия согласия, версия настоящей политики и платформа Android;
  • программа тренировок: упражнения, описания техники, веса и повторения;
  • по отдельному разрешению — суммарно сожжённые за текущий день калории из Health Connect;
  • по отдельному разрешению — примерное местоположение устройства для получения текущей погоды;
  • технические сведения, необходимые для сетевого соединения, защиты и диагностики сервисов, включая IP-адрес и служебные сведения запросов;
  • при показе рекламы — технические сведения устройства и рекламного запроса, необходимые Yandex Mobile Ads для загрузки, показа и диагностики баннера.

Пароль обрабатывается Firebase Authentication и не сохраняется в хранилище тренировок приложения.

2. Аккаунт и синхронизация

Данные аккаунта и программы тренировок используются для регистрации, входа, восстановления доступа, синхронизации между устройствами, поддержки и обеспечения безопасности. При создании аккаунта пользователь отдельно предоставляет согласие для аккаунта и облачной синхронизации. Гостевой режим не отправляет тренировки в облако.

3. Health Connect

FitTrack читает только суммарно сожжённые калории за текущий день после явного разрешения пользователя. Эти сведения отображаются на устройстве, не сохраняются приложением, не включаются в облачную синхронизацию и не передаются Firebase, рекламным системам или иным третьим лицам. Разрешение необязательно и может быть отозвано в настройках Health Connect.

4. Местоположение и погода

После нажатия «Показать погоду» FitTrack запрашивает разрешение Android только на примерное местоположение. Приблизительные координаты передаются сервису Open-Meteo по защищённому соединению для получения текущей погоды. FitTrack не сохраняет координаты, не включает их в облачную синхронизацию и не передаёт рекламному SDK. Open-Meteo также получает технические сведения сетевого запроса, включая IP-адрес. Разрешение необязательно, может быть отозвано в настройках Android и не ограничивает остальные функции приложения.

5. Firebase, территории обработки и хранение

Для аутентификации и синхронизации используются Firebase Authentication и Cloud Firestore (Google). Firebase Authentication обрабатывает данные аутентификации в США, а Cloud Firestore — в выбранном для проекта регионе инфраструктуры Google. Использование облачного режима может включать трансграничную передачу данных. Локальный гостевой режим не использует Firebase.

Локальные данные находятся во внутреннем хранилище Android. Сетевой обмен выполняется по TLS, незашифрованный HTTP запрещён, системное резервное копирование данных приложения отключено. Для защиты Firebase release-клиент может передавать токен целостности Play Integrity.

6. Реклама Яндекса

В публичной RuStore-сборке подключён Yandex Mobile Ads SDK с рекламным местом R-M-19665468-1. SDK может получить IP-адрес и технические сведения устройства и рекламного запроса, необходимые для загрузки, показа и диагностики баннера.

FitTrack передаёт рекламному SDK значение setUserConsent(false), отключает передачу геолокации и удаляет разрешение на Advertising ID (AD_ID) из итоговой сборки. Персонализированная реклама не включена. Отдельное отключение рекламного баннера в приложении не предусмотрено.

7. Срок хранения и удаление

Локальные данные хранятся до удаления данных приложения или самого приложения. Облачные данные хранятся до удаления учётной записи, отзыва согласия либо достижения целей обработки, если более длительная обработка не требуется законом. Удалить учётную запись и облачные тренировки можно на экране «Аккаунт».

После отзыва согласия облачный аккаунт и синхронизация становятся недоступны. Локальный гостевой режим продолжает работать.

10. Изменения политики

При изменении состава данных, целей обработки, облачных сервисов или рекламной конфигурации оператор обновит эту политику и её версию. Необходимость получения нового согласия определяется с учётом характера изменений и требований применимого законодательства.

Предыдущие редакции остаются опубликованными без изменений для выпущенных ранее версий приложения.
